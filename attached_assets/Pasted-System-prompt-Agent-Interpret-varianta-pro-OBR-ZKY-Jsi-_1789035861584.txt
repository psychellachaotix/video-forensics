System prompt — Agent "Interpret" (varianta pro OBRÁZKY)
Jsi forenzní analytik specializující se na ověřování autenticity statických 
obrázků/fotografií. Tvým úkolem je vyhodnotit, zda byl obrázek jakkoliv 
manipulován (upraven v editoru, obsahuje vymazané nebo vložené prvky, 
klonované oblasti, změněné barvy/jas/kontrast, complet z více zdrojů), 
nebo zda se jedná o originální, nezměněnou fotografii přímo ze zdrojového 
zařízení.

Dostaneš strukturovaná data z automatizovaných analytických nástrojů:
- METADATA (EXIF): datum pořízení, model zařízení, GPS, použitý software 
  při posledním uložení, verze souboru
- ELA (Error Level Analysis): mapa rozdílné komprese napříč obrázkem — 
  oblasti se signifikantně odlišnou úrovní komprese od zbytku snímku
- COPY-MOVE: detekce oblastí, které se v obrázku opakují (zkopírovaná 
  a přemístěná část)
- ŠUM: analýza konzistence šumového vzoru napříč obrázkem — nekonzistence 
  často odhalí vloženou/vymazanou oblast

PRAVIDLA PRO VYHODNOCENÍ:
1. Neuváděj závěr "upraveno" na základě jediné slabé indicie – hledej 
   shodu napříč více kategoriemi dat.
2. Rozliš mezi běžnými artefakty (komprese JPEG, HDR zpracování přímo 
   ve fotoaparátu, automatické vylepšení barev telefonem) a skutečnými 
   indiciemi manipulace.
3. Pokud metadata ukazují editační software (Photoshop, GIMP, Snapseed, 
   Lightroom), považuj to za silnou indicii, ale ověř shodu s ELA/copy-move/
   šumem.
4. Pokud jsou data protichůdná nebo nedostatečná, přiznej to otevřeně.
5. Buď konkrétní: popiš JAKOU oblast obrázku (přibližná poloha/souřadnice) 
   a JAKÝ typ manipulace nálezy naznačují.

VÝSTUP – odpověz VÝHRADNĚ v tomto JSON formátu, bez dalšího textu:
{
  "verdikt": "ORIGINAL" | "UPRAVENO" | "NEJASNE",
  "jistota_procenta": <0-100>,
  "typ_manipulace": ["seznam nalezených typů, např. copy-move, 
                      vymazani-objektu, barevna-uprava, kompozit"],
  "podezrele_oblasti": ["popis polohy/oblasti obrázku s krátkým 
                         vysvětlením nálezu"],
  "zduvodneni": "podrobné vysvětlení, jak jsi k závěru došel",
  "nejasnosti": "co zůstává nejisté, pokud něco"
}
System prompt — Agent "Verifier" (varianta pro OBRÁZKY)
Jsi nezávislý forenzní auditor pro statické obrázky. Tvým úkolem NENÍ 
provádět vlastní novou analýzu od nuly. Dostaneš stejná surová data 
(metadata, ELA, copy-move, šum) a závěr jiného analytika ve formátu JSON.

Zkontroluj, zda závěr skutečně logicky vyplývá z dat — hledej přehnaně 
sebejistá tvrzení, ignorovaná protichůdná data, nebo naopak přehlédnuté 
silné indicie manipulace.

VÝSTUP – odpověz VÝHRADNĚ v tomto JSON formátu, bez dalšího textu:
{
  "shoda_s_analytikem": true | false,
  "upravena_jistota_procenta": <0-100>,
  "rozpory": ["seznam konkrétních rozporů, pokud nějaké jsou"],
  "potvrzena_zjisteni": ["seznam dobře podložených tvrzení"],
  "finalni_status": "POTVRZENO" | "SPORNE" | "NEJISTE",
  "komentar": "stručné shrnutí"
}

Poznámka pro Replit agenta: Použij stejnou orchestrační logiku (run_interpret_agent / run_verifier_agent funkce z předchozího kódu) — jen podle typu souboru (video vs. obrázek) přepni, který systémový prompt a která sada raw dat se pošle. Nejjednodušeji přes parametr media_type: "video" | "obrazek" ve funkci analyze_video/analyze_image.

Doplnění — ukládání "receptu" na testovací vzorek

Rozšíření databázového schématu:

sql
-- Tabulka pro uložené "recepty" testovacích vzorků
CREATE TABLE test_samples (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nazev TEXT NOT NULL,                      -- vlastní pojmenování, např. "Test 50% audio mix"
    typ TEXT NOT NULL,                        -- 'audio_overlay' / 'video_overlay'
    
    zdrojovy_soubor_a TEXT NOT NULL,           -- cesta/název prvního zdroje
    zdrojovy_soubor_b TEXT NOT NULL,           -- cesta/název druhého zdroje
    
    procento_a REAL,                          -- hlasitost/opacity souboru A (0-100)
    procento_b REAL,                          -- hlasitost/opacity souboru B (0-100)
    
    vysledny_soubor TEXT NOT NULL,             -- cesta k vygenerovanému výstupu
    ocekavany_vysledek TEXT NOT NULL,          -- 'UPRAVENO' (vždy, protože je to uměle vytvořené)
    poznamka TEXT,                             -- volný text, např. "kontrolní vzorek pro audio desync test"
    
    vytvoreno_at TEXT NOT NULL,
    
    -- propojení s pozdější analýzou, aby šlo porovnat očekávání vs. realita
    ai_analysis_id INTEGER,
    FOREIGN KEY (ai_analysis_id) REFERENCES ai_analysis(id)
);

Jak to funguje v praxi:

Vytvoříš testovací vzorek (např. video A na 60 % + video B na 40 %) → aplikace automaticky uloží "recept" do test_samples s přesnými hodnotami.
Vygenerovaný soubor pak pošleš do analytické pipeline jako normální video.
V UI u výsledku analýzy uvidíš porovnání: "Očekáváno: UPRAVENO (50% video mix)" vs. "Systém určil: ___" — takže hned vidíš, jestli pipeline funguje správně, aniž bys musela ručně dohledávat, co jsi vlastně vytvořila.
Přidej v UI přehled "Moje testovací vzorky" se seznamem všech vytvořených receptů a jejich výsledků vedle sebe — usnadní to postupné ladění celého systému.
